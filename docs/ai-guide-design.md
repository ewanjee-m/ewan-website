# AI 길 안내 디자인

## 목표

길 안내는 방문자가 현재 날씨 또는 오늘의 포춘을 선택하면 월드의 목적지 하나와 그 방향을 추천한다. 추천은 이동을 대신하지 않는다.

- 플레이어 위치, 속도, 방향, 점프와 입력 상태를 바꾸지 않는다.
- 자동 걷기와 자동 전체 지도 이동을 실행하지 않는다.
- 방문자는 추천을 무시하고 자유롭게 이동할 수 있다.
- 추천 중에도 전체 지도를 열어 다섯 장소 어디로든 이동할 수 있다.
- 미니맵은 길 안내와 같은 탐색 스냅샷을 읽지만 추천 상태와 독립적으로 동작한다.

## 방문자 흐름

1. 월드 왼쪽 위의 길 안내 버튼을 연다.
2. `현재 날씨` 또는 `오늘의 포춘`을 선택한다.
3. 요청 중에는 진행 상태와 취소 버튼을 표시한다.
4. 성공하면 목적지, 현재 위치 기준 방향, 테마와 데이터 설명을 표시한다.
5. 패널을 닫아도 추천 목적지와 방향 표시는 유지한다.
6. `다시 선택`을 누르면 입력 선택 화면으로 돌아간다.

길 안내 패널이 열린 동안 미니맵은 화면 겹침을 피하려고 숨는다. 패널을 닫으면 같은 위치와 진행 방향으로 다시 표시한다.

## 허용 값

목적지는 다음 정적 목록으로 제한한다.

| ID | 장소 |
| --- | --- |
| `airport` | 공항 |
| `tokyo` | 도쿄 |
| `gyukatsu` | 규카츠 |
| `sakura` | 벚꽃 수로 |
| `hanabi` | 하나비 |

테마는 `fresh_start`, `focus`, `connection`, `curiosity`, `rest`, `celebration`만 허용한다. 요청 방식은 `weather`, `fortune`만 허용한다.

현재 장소는 추천 후보에서 제외한다. 서버 응답의 목적지, 테마와 근거가 허용 목록 또는 요청 방식과 다르면 사용하지 않는다.

## 요청 계약

포춘 요청:

```json
{
  "mode": "fortune",
  "currentZoneId": "airport",
  "allowedDestinationIds": ["tokyo", "gyukatsu", "sakura", "hanabi"],
  "tokyoDate": "2026-07-23"
}
```

날씨 요청:

```json
{
  "mode": "weather",
  "currentZoneId": "airport",
  "allowedDestinationIds": ["tokyo", "gyukatsu", "sakura", "hanabi"],
  "tokyoDate": "2026-07-23",
  "weatherCode": 1,
  "temperatureC": 27,
  "observedAt": "2026-07-23T05:00:00Z"
}
```

응답:

```json
{
  "destinationId": "sakura",
  "themeId": "rest",
  "basis": "weather"
}
```

객체는 정의된 키만 허용한다. 목적지 목록은 중복이 없어야 하고 현재 장소를 포함할 수 없다.

## 날씨

- 도쿄 좌표는 `35.6895`, `139.69171`로 고정한다.
- 날짜와 자정은 `Asia/Tokyo`를 사용한다.
- 방문자 위치 권한을 요청하지 않는다.
- 날씨 관측 시각은 ISO UTC 시각이어야 한다.
- 현재 시각보다 `30분` 이상 오래됐거나 `5분` 이상 미래인 값은 AI 입력으로 사용하지 않는다.
- 실제 날씨를 받을 수 없으면 계절 기본값을 현재 날씨처럼 표시하지 않는다.
- Open-Meteo 출처 링크를 길 안내 패널에 표시한다.

## 포춘

- `Asia/Tokyo`의 날짜를 기준으로 한다.
- 이름, 생년월일, 성별과 위치를 입력받지 않는다.
- 오락 목적의 안내이며 의료, 법률, 금융 판단이나 사실 예측으로 표현하지 않는다.
- 같은 요청 입력은 안정적인 로컬 해시로 같은 추천을 만들 수 있다.

## 실패와 로컬 대체

API 키가 없거나 서버, OpenAI 또는 날씨 요청이 실패해도 월드와 지도는 계속 동작한다.

로컬 대체 추천은 다음 규칙을 지킨다.

- 현재 장소를 제외한다.
- 허용된 목적지와 테마만 사용한다.
- 도쿄 날짜, 요청 방식과 허용된 날씨 값으로 안정적인 결과를 만든다.
- 이미 화면에 유효한 추천이 있으면 실패 종류에 따라 유지할 수 있다.
- 취소는 새 추천을 적용하지 않는다.

## 방향 계산

길 안내는 플레이어의 현재 논리 위치와 진행 방향, 목적지 도착점으로 `straight`, `left`, `right`, `turnAround` 중 하나를 계산한다.

이 계산은 카메라 회전이나 화면 드래그에 의존하지 않는다. 활성 월드 카메라는 승인 원화 표시 창이며 방문자가 회전하는 카메라 조작을 제공하지 않는다.

## 모바일 상호작용

검증 기준은 `390x844`다.

- 화면 왼쪽 이동 조작으로 플레이어를 움직인다.
- 오른쪽 아래 점프 버튼을 사용한다.
- 위치 복귀 버튼은 플레이어를 시작점으로 돌린다.
- 길 안내 패널은 상단 UI와 오른쪽 조작 영역을 피해 열리고 내부를 스크롤할 수 있다.
- 미니맵을 접거나 펼칠 수 있다.
- 전체 지도에서 장소를 선택해 한 번에 이동할 수 있다.

길 안내 패널은 포인터 이벤트가 월드 이동으로 전달되지 않게 막는다. 패널을 닫은 뒤 이동 조작과 전체 지도를 그대로 사용할 수 있다.

## 접근성

- 닫힌 상태의 열기 버튼은 `aria-expanded="false"`를 제공하고, 패널이 열리면 열기 버튼 대신 패널을 표시한다.
- 요청과 결과 상태는 `role="status"`, `aria-live="polite"`로 알린다.
- 닫기 버튼과 `Escape`를 지원한다.
- 결과 제목과 닫기 버튼으로 초점을 명시적으로 옮긴다.
- 모든 버튼은 키보드로 사용할 수 있다.
- 패널 안의 버튼은 최소 `44px` 높이의 조작 영역을 제공한다.

## 개인정보와 보안

- `OPENAI_API_KEY`는 서버 환경에서만 읽는다.
- 키를 `NEXT_PUBLIC_*`, 브라우저 코드, 저장소 또는 `public` 파일에 넣지 않는다.
- 이름, 이메일, 생년월일, 성별과 방문자 위치를 수집하지 않는다.
- 자유 입력을 서버로 보내지 않는다.
- 허용된 열거형과 수치 범위를 통과한 값만 서버 계약으로 사용한다.
- 화면 문구는 한국어, 일본어, 영어 메시지 사전에서 가져온다.
