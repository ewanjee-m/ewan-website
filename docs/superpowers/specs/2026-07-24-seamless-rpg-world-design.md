# 연속형 3D RPG 월드 설계

## 목표

공항, 도쿄 마을, 규카츠 거리, 사쿠라 운하, 하나비 축제장을 하나의 연속형 3D 월드로 구성한다. 캐릭터는 순간이동이나 지역 로딩 없이 모든 장소를 직접 이동한다. 이동에 따라 주변 건물, 지형, 소품, 조명, 효과와 카메라 시점이 실제 3D 공간에서 변해야 한다.

완성된 월드는 다음 경험을 제공해야 한다.

- 공항에서 하나비까지 직접 이동할 수 있다.
- 고정 배경 이미지를 확대하거나 옮기는 방식에 의존하지 않는다.
- 데스크톱과 모바일에서 카메라를 자유롭게 회전할 수 있다.
- 카메라는 캐릭터를 부드럽게 추적하고 장애물을 피한다.
- 각 지역의 색감과 대표 요소는 현재 기준 이미지의 인상을 유지한다.
- 미니맵과 전체 지도는 실제 월드 좌표와 일치한다.
- 전체 지도는 위치 안내만 제공하며 순간이동 기능을 제공하지 않는다.
- 실제 브라우저와 공개 URL에서 이동, 카메라, 상호작용, 오류 상태를 검증한다.

## 범위

### 포함

- 하나의 React Three Fiber Canvas에서 유지되는 야외 연속 월드
- 공항, 도쿄, 규카츠, 사쿠라, 하나비 지역
- 지역을 잇는 도로, 광장, 보행 공간, 운하와 다리
- 남성·여성 플레이어 3D 모델
- 지역별 NPC와 주요 입구 상호작용
- 걷기, 달리기, 점프, 충돌, 재시작
- 데스크톱·모바일 카메라 회전과 자동 추적
- 미니맵, 전체 지도, 지역 안내
- 성능 조절, 오류 화면, 자산 실패 처리
- 자동 테스트, Computer Use 확인, 공개 URL 검증

### 제외

- 건물 내부 이동
- 전체 월드 순간이동과 지역 빠른 이동
- 지역별 로딩 화면
- 사실적인 도시 재현
- 월드 전체를 하나의 대형 외부 3D 모델로 제작하는 방식
- WebGL 실패 시 고정 이미지 월드로 전환하는 방식

## 확정된 제품 결정

- 월드는 로딩 없이 연결된 하나의 3D 공간이다.
- 시각 방향은 기준 이미지의 색감과 지역 특징을 반영한 스타일형 3D다.
- 지형, 길, 충돌, 반복 건물은 데이터와 절차형 geometry로 구성한다.
- 지역을 대표하는 장소는 전용 3D 구성 요소로 강화한다.
- 카메라는 마우스·터치 회전을 지원하고 이동 중 캐릭터 뒤로 부드럽게 복귀한다.
- 전체 지도와 미니맵은 이동 권한을 갖지 않는다.
- 야외 이동과 주요 장소 상호작용에 집중한다.
- 공항에서 하나비까지 정속 이동 시간은 50~80초를 목표로 한다.
- 주변 탐색과 상호작용을 포함한 일반 이동 시간은 약 1~2분을 목표로 한다.

## 현재 구현에서 바꾸는 경계

현재 활성 흐름은 다음과 같다.

```text
ExperienceShell
→ WorldView
→ FlatWorldCanvas
→ FlatWorldSession
→ RpgWorldBackdrop
→ RpgReferenceSceneComposition
```

이 흐름은 하나의 기준 이미지를 카메라 위치에 따라 변환하고, 지역별 전경 마스크를 겹쳐 깊이를 표현한다. 캐릭터 좌표는 변하지만 배경은 실제 공간이 아니다.

목표 흐름은 다음과 같다.

```text
ExperienceShell
→ WorldView
→ SeamlessWorldCanvas
   ├─ WorldRuntime
   ├─ WorldScene
   ├─ PlayerAndNpcs
   ├─ InteractionPoints
   └─ ChaseOrbitCamera
→ MiniMap
→ ReadOnlyWorldMap
```

활성 경로에서 다음 요소를 제거한다.

- `FlatWorldCanvas`
- `RpgWorldBackdrop`
- `RpgReferenceSceneComposition`
- 고정 이미지 기준 카메라 배치
- 지도 선택에 따른 이동 요청

다음 데이터와 기능은 유지하거나 렌더러 중립 형태로 정리한다.

- `RpgWorldModel`의 월드 경계, 지역, 길, 전이 구간, 도착점, 운하, 다리
- 현재 RPG 좌표 기반 이동과 충돌 규칙
- `RpgWorldGeometry`의 지역·경로 판정
- 미니맵과 전체 지도의 좌표 투영
- 캐릭터 선택과 3D 모델 자산
- NPC 모델과 상호작용 콘텐츠
- 키보드, 조이스틱, 점프, 재시작 입력
- 적응형 품질 설정

구형 구면 월드 좌표를 사용하는 `WorldSession`은 재사용하지 않는다. 연속 월드는 현재 직교 RPG 좌표와 보행 가능 영역을 기준으로 동작한다.

### 3D 모듈 재사용 결정

중복 구현을 막기 위해 모듈별 결정을 고정한다.

| 모듈 | 결정 | 적용 방식 |
| --- | --- | --- |
| `RpgPlayerCharacter3d` | 재사용 | 플레이어 GLB, toon 재질, 카메라 거리 가시성 로직을 유지한다. 자산 실패 경계를 추가한다. |
| `RpgNpcCharacter3d` | 재사용 | NPC GLB와 가시성 로직을 유지하고 상호작용 범위와 연결한다. |
| `RpgCharacterMotion3d` | 재사용 | 대기·걷기·점프 pose를 유지하고 걷기·달리기 속도 비율을 입력으로 확장한다. |
| `RpgCameraCollision` | 재사용 | 최소 boom 거리 `2.6`과 건물·기둥 충돌을 새 카메라에 연결한다. |
| `RpgCameraObstacleSources` | 재사용·확장 | 절차형 건물과 대표 장소의 충돌 물체를 같은 형식으로 공급한다. |
| `AdaptiveQuality` | 재사용 | 2초 표본, 42FPS 하향, 55FPS 회복 기준을 유지하고 측정 결과를 노출한다. |
| `RpgTownArchitecture` | 재사용 | 반복 건물과 인스턴싱의 기본 렌더러로 사용한다. |
| `RpgTownDetails` | 재사용 | 거리 장식과 지역별 소품을 공급한다. |
| `WorldLandmarks` | 분리·재사용 | 지역별 대표 장소 구성 요소로 나누고 현재 월드 좌표에 배치한다. |
| `RpgHanabiLayout` | 재사용 | 불꽃 위상과 배치를 유지하고 품질 단계별 입자 수를 적용한다. |
| `FlatWorldSession` | 대체 | 빠른 이동과 평면 높이 가정을 제거한 `WorldRuntime`으로 역할을 옮긴다. |
| `WorldSession` | 사용하지 않음 | 구면 좌표와 quaternion 이동은 연속 RPG 월드 계약과 맞지 않는다. |
| `CameraRig` | 대체 | 회전 입력이 없는 호환 동작을 `ChaseOrbitCamera`로 교체한다. |
| `RpgTownScene` | 대체 | `null` 장면 계약을 `WorldScene` 조립부로 교체한다. |
| `WorldCanvas` | 조립부만 참고 | 구형 구면 세션을 제외하고 Canvas 설정, 품질 감시, 오류 경계 패턴만 가져온다. |

## 시스템 구조

### `WorldView`

`WorldView`는 3D Canvas와 화면 위 UI를 조립한다.

- 선택한 캐릭터를 `SeamlessWorldCanvas`에 전달한다.
- 키보드, 모바일 조이스틱, 카메라 입력을 연결한다.
- 월드가 발행한 탐색 상태를 안내 화면과 지도에 전달한다.
- 상호작용 모달이 열릴 때 이동 입력을 잠근다.
- 재시작 요청만 공항 시작 위치로 전달한다.
- 전체 지도에서 이동 요청을 만들지 않는다.

### `SeamlessWorldCanvas`

Canvas는 월드 진입부터 이탈까지 한 번만 생성한다.

- 모든 야외 지역을 같은 장면에 올린다.
- 지역 이동 중 장면 루트를 교체하지 않는다.
- 이동 좌표, 캐릭터, 카메라, 충돌과 장면을 같은 프레임에서 갱신한다.
- 월드 상태를 UI에 필요한 빈도로만 발행한다.
- Canvas 준비 여부와 자산 오류를 명시적으로 보고한다.

### `WorldRuntime`

`WorldRuntime`은 플레이 상태의 단일 기준이다.

```text
입력
→ 카메라 기준 이동 방향
→ 이동 거리 계산
→ 보행 가능 영역과 장애물 충돌 검사
→ 위치·방향·수직 상태 확정
→ 지역·전이 구간·상호작용 대상 판정
→ 장면·카메라·지도 상태 발행
```

런타임이 소유하는 값은 다음과 같다.

- 캐릭터 위치와 방향
- 대기, 걷기, 달리기, 점프 상태
- 현재 지역 또는 전이 구간
- 가까운 NPC 또는 입구
- 카메라 회전 입력 상태
- 재시작 상태

지도와 UI는 런타임의 위치를 표시할 수 있지만 수정할 수 없다.

UI 스냅샷은 기본 `10Hz`로 발행해 위치 표시 지연을 `100ms` 이하로 제한한다. 지역, 전이 구간, 상호작용 대상, 오류 상태가 바뀌면 다음 예약 주기를 기다리지 않고 즉시 발행한다.

### `WorldScene`

`WorldScene`은 다음 층을 같은 좌표에 배치한다.

```text
WorldScene
├─ WorldSurfaces
├─ RoadsAndPlazas
├─ CanalAndBridge
├─ BatchedArchitecture
├─ StreetLife
├─ SignatureLandmarks
├─ RegionLighting
└─ WorldEffects
```

- 지형, 도로, 광장, 운하, 다리는 월드 데이터에서 생성한다.
- 반복 건물과 거리 장식은 인스턴싱을 사용한다.
- 공항 터미널, 규카츠 상점가, 사쿠라 다리, 하나비 축제장처럼 식별성이 중요한 장소는 전용 구성 요소로 만든다.
- 장면 배치는 지도와 충돌이 사용하는 좌표에서 파생한다.
- 시각 배치만 따로 관리하는 두 번째 좌표 체계를 만들지 않는다.

## 월드 배치와 지역 표현

주요 이동 흐름은 다음과 같다.

```text
공항
→ 도쿄 마을
→ 규카츠 거리
→ 사쿠라 운하
→ 하나비 축제장
```

공항에서 규카츠로 이어지는 보조 길과 짧은 우회 경로를 유지해 하나의 통로처럼 보이지 않게 한다.

### 공항

- 터미널, 버스, 정류장, 관제 시설
- 넓은 진입 광장과 낮은 건물
- 밝은 하늘색과 중성 회색 중심
- 공항 여행자 NPC와 입구 상호작용

### 도쿄 마을

- 상대적으로 높은 건물과 밀도 높은 상점가
- 교차로, 횡단보도, 간판, 전신주
- 공항보다 좁은 시야와 높은 수직 요소
- 도쿄 지역 NPC와 안내 지점

### 규카츠 거리

- 낮은 마치야 건물, 골목, 화로와 음식점 소품
- 따뜻한 갈색과 주황색 조명
- 다른 지역보다 가까운 카메라 거리
- 규카츠 셰프 NPC와 가게 입구 상호작용

### 사쿠라 운하

- 운하, 다리, 벚나무, 수변 산책로
- 물은 보행 불가 영역이며 다리로만 건넌다.
- 분홍색 식생과 밝은 자연광
- 사쿠라 방문자 NPC와 다리 상호작용

### 하나비 축제장

- 도리이, 등불, 노점, 축제 광장
- 하늘의 불꽃과 지면 조명을 분리해 성능을 조절한다.
- 붉은색, 금색, 짙은 남색 중심
- 유카타 NPC와 축제 상호작용

지역의 변화는 경계에서 한 번에 바꾸지 않는다. 전이 구간에서 다음 값을 보간한다.

- 안개와 하늘 색
- 주광과 보조광의 색·세기
- 거리 장식 밀도
- 식생 종류
- 환경 효과
- 배경음과 지역 음량
- 카메라 기본 거리

## 입력 계약

### 데스크톱

| 입력 | 동작 |
| --- | --- |
| `WASD`, 방향키 | 카메라 수평 방향 기준 이동 |
| `Shift` + 이동 | 달리기 |
| `Space` | 점프 |
| 빈 월드 드래그 | 카메라 회전 |
| `E`, `Enter` | 가까운 대상과 상호작용 |
| `R` | 공항 시작 위치로 재시작 |
| `Escape` | 지도·상호작용 화면 닫기 |

카메라 드래그는 Canvas 배경에서 시작한 포인터만 캡처한다. 버튼, 지도, 대화상자와 조이스틱에서 시작한 포인터는 카메라에 전달하지 않는다.

### 모바일

- 왼쪽 조이스틱은 카메라 수평 방향 기준 이동을 제어한다.
- 조이스틱 크기가 `0.85` 이상이면 달리기, 그보다 작으면 입력 크기에 비례한 걷기로 처리한다.
- 화면 오른쪽 `55%`에서 시작한 한 손가락 드래그는 카메라 회전을 제어한다.
- 점프, 상호작용, 재시작은 화면 버튼을 사용한다.
- 두 손가락 확대·축소와 브라우저 기본 스크롤은 월드 화면에서 사용하지 않는다.

대각선 입력은 정규화해 직선 이동보다 빨라지지 않게 한다.

## 이동과 충돌

보행 가능 영역은 다음 합성으로 계산한다.

```text
도로
+ 광장
+ 보행 공간
+ 지정된 잔디
- 건물 충돌 영역
- 물
- 큰 장식물
```

- 캐릭터의 발 위치를 기준으로 충돌을 검사한다.
- 막힌 이동은 가능한 축 방향으로 미끄러지게 처리해 모서리에 불필요하게 걸리지 않게 한다.
- 캐릭터는 보행 가능 영역 밖으로 나가지 않는다.
- 운하는 다리 표면을 통할 때만 건널 수 있다.
- 점프는 장애물을 넘어가는 우회 수단이 아니며 착지점도 보행 가능해야 한다.
- 재시작은 공항 시작 위치와 안전한 방향으로 캐릭터를 되돌린다.

걷기 속도는 `1.61 world units/s`, 달리기 속도는 `1.9 world units/s`다. 속도는 프레임 시간이 달라도 같아야 하며 한 프레임의 이동 계산은 최대 `0.25s`로 제한한다.

이동 시간은 다음 고정 경로에서 측정한다.

```text
RPG_WORLD_SPAWN
→ gyukatsu-cross-street 서쪽 경계 [-27, -2.973191]
→ airport-arrival-road 중심 [-29, -2.973191]
→ airport-arrival-road 북쪽 [-29, 20]
```

이 경로는 `tests/fixtures/rpg-canonical-route.ts`의 단일 상수로 관리한다. 모든 선분을 `0.1 world units` 이하 간격으로 표본화했을 때 `isWalkable`이 모두 `true`여야 한다.

경로의 평면 길이는 약 `122.09 world units`다. 자동 경로 입력에서 걷기는 약 `75.8초`, 달리기는 약 `64.3초`가 되며 각 결과의 허용 범위는 목표값의 `±5%`다. 측정 중 충돌을 우회하기 위한 추가 이동은 시간 계산에서 제외하지 않는다.

### 지면 높이와 점프

런타임의 수직 위치는 다음 식을 사용한다.

```text
playerY = getSurfaceHeight([x, z]) + jumpOffset
```

- 평지의 지면 높이는 `0`이다.
- 다리 높이는 `RPG_WORLD_BRIDGE.surfaceHeight`와 `archRise`에서 계산한다.
- 캐릭터 발, 그림자, 카메라 기준점은 같은 지면 높이를 사용한다.
- 지도는 수직 높이를 무시하고 `[x, z]`만 투영한다.
- 점프 시작 속도 `6 world units/s`, 중력 `15 world units/s²`를 유지한다.
- 점프 중 이동한 뒤 착지할 때 현재 `[x, z]`의 지면 높이에 맞춘다.
- 발과 지면 사이 오차는 `0.02 world units` 이하여야 한다.
- 다리 경사 이동에서 한 프레임 사이 수직 위치가 불연속적으로 바뀌지 않아야 한다.

## 캐릭터 표현

- 선택된 남성·여성 GLB 모델을 플레이어로 사용한다.
- 모델의 기준점은 발바닥에 맞춘다.
- 캐릭터는 이동 방향을 향해 감속 회전한다.
- 대기, 걷기, 달리기, 점프 상태를 런타임 이동 값에서 결정한다.
- 애니메이션이 없는 자산은 몸 기울기, 팔·다리 보조 동작, 그림자로 상태를 구분한다.
- 캐릭터 모델을 불러오지 못하면 크기와 방향을 확인할 수 있는 기본 3D 캐릭터를 표시한다.
- 모델 오류가 월드 전체를 중단하지 않게 자산 경계를 분리한다.

## 카메라

카메라는 자유 회전과 추적을 함께 제공한다.

### 조작

- 데스크톱은 빈 월드 드래그로 카메라를 회전한다.
- 모바일은 왼쪽 조이스틱으로 이동하고 오른쪽 화면 드래그로 카메라를 회전한다.
- UI 버튼, 지도, 대화상자 위의 포인터 입력은 카메라로 전달하지 않는다.
- 이동 방향은 카메라의 수평 방향을 기준으로 계산한다.
- 수평 회전 범위는 제한 없는 `360°`다.
- 아래를 내려다보는 수직 각도는 수평선 기준 `18°~55°`로 제한한다.
- 데스크톱 감도는 `0.004 rad/CSS px`, 터치 감도는 `0.006 rad/CSS px`다.
- 기본 입력은 수직축을 뒤집지 않는다.

### 추적

- 카메라 기준점은 캐릭터의 어깨 높이 근처에 둔다.
- 위치와 회전은 프레임 시간 기반 감쇠로 보간한다.
- 사용자가 회전하는 동안 자동 복귀를 중단한다.
- 회전 입력이 끝난 뒤 캐릭터가 계속 이동하면 `0.8초` 후 이동 방향 뒤로 복귀한다.
- 캐릭터가 서 있으면 사용자가 정한 방향을 유지한다.
- 각도 복귀는 가장 짧은 회전 방향을 사용한다.
- 위치 추적 감쇠 반감기는 `0.12초`, 회전 추적 감쇠 반감기는 `0.18초`다.
- 마지막 카메라 입력 뒤 `0.8초` 동안 자동 복귀를 시작하지 않는다.
- 자동 복귀 시작 후 `1.2초` 안에 카메라 수평 방향과 캐릭터 이동 반대 방향의 차이가 `5°` 이하여야 한다.

### 장애물 회피

- 캐릭터 기준점에서 원하는 카메라 위치까지 장애물 충돌을 검사한다.
- 건물이나 큰 물체가 사이에 있으면 카메라 거리를 줄인다.
- 최소 카메라 거리는 `2.6`을 유지한다.
- 장애물을 벗어나면 `0.2초` 감쇠 반감기로 원래 거리로 복귀한다.
- 최소 거리에서도 캐릭터가 가려지면 시야를 막는 물체를 일시적으로 투명 처리한다.
- 카메라가 충돌 물체 안에 있거나 캐릭터가 화면 안전 영역 밖에 있는 상태를 개발·테스트 환경에서 감지한다.
- 장애물을 벗어난 뒤 boom 거리 복귀 감쇠 반감기는 `0.2초`다.
- 시야 차단이 `250ms` 이상 지속되면 차단 물체를 `100ms` 안에 투명 처리하고, 차단이 끝나면 `200ms`에 걸쳐 원래 불투명도로 복귀한다.
- 카메라 충돌 계산 결과가 유한하지 않으면 직전 안전 위치를 유지하고 진단 상태를 발행한다.

화면 안전 영역은 다음과 같다.

- 데스크톱 `1440x900`: 캐릭터 전체가 화면 가로 `15%~85%`, 세로 `10%~92%` 안에 있어야 한다.
- 모바일 `390x844`: 상단 UI를 제외한 `(0,64,390,780)` 안에서 캐릭터 전체가 가로 `10%~90%`, 세로 `8%~94%` 안에 있어야 한다.
- 일반 이동 중 안전 영역 이탈은 연속 `250ms`를 넘지 않아야 한다.

### 지역별 기본값

기본 FOV는 데스크톱 `45°`, 모바일 `52°`다. 지역 기본값은 다음과 같다.

| 지역 | 기본 거리 | 기본 pitch |
| --- | ---: | ---: |
| 공항 | `7.8` | `28°` |
| 도쿄 | `6.6` | `34°` |
| 규카츠 | `5.6` | `38°` |
| 사쿠라 | `6.8` | `32°` |
| 하나비 | `8.0` | `28°` |

- 모바일 기본 거리는 표 값의 `0.88배`다.
- 지역 기본값은 전이 진행률 `0~1`에 `smoothstep`을 적용해 보간한다.
- 카메라 컷이나 지역 진입 애니메이션은 사용하지 않는다.

## 지도와 안내

미니맵과 전체 지도는 월드 런타임의 위치·방향을 읽는다.

- 미니맵은 캐릭터 위치, 방향, 도로, 다리, 주요 장소를 표시한다.
- 전체 지도는 다섯 지역과 현재 위치를 표시한다.
- 지역 선택은 설명과 강조 상태만 바꾼다.
- 지도는 이동, 재배치, 빠른 이동 요청을 만들지 않는다.
- 지도 투영은 월드 모델 좌표에서 계산한다.
- 기준 `1817x866` 좌표에서 다섯 도착점의 투영 오차는 각각 `0.5 CSS px` 이하다.
- 임의의 보행 가능 위치를 지도 좌표로 변환하고 다시 월드 좌표로 되돌렸을 때 평면 오차는 `0.1 world units` 이하다.
- 캐릭터 방향과 지도 표식 방향의 차이는 `2°` 이하다.
- 런타임 위치가 바뀐 뒤 지도 표식 반영 지연은 `100ms` 이하다.

빠른 이동 제거는 UI만 숨기는 것으로 끝내지 않는다.

- 활성 입력 계약에서 `queueTravel`과 `consumeTravel`을 제거한다.
- 활성 런타임에서 `fastTravel`, `teleport`, 임의 `setPosition`을 외부에 노출하지 않는다.
- `RpgWorldMap`은 `onTravel` 속성을 받지 않는다.
- 지도 장소 버튼을 누른 뒤 `500ms` 동안 위치와 revision이 이동 때문에 바뀌지 않아야 한다.
- 공항으로 좌표를 바꿀 수 있는 공개 동작은 재시작 하나뿐이다.

## 상호작용

- NPC와 주요 입구는 월드 좌표 기반 상호작용 범위를 가진다.
- 캐릭터가 범위에 들어오고 대상을 바라볼 때 상호작용 버튼을 표시한다.
- 상호작용이 열리면 이동과 점프 입력을 잠근다.
- 카메라는 현재 구도를 유지하고 월드 효과는 계속 실행한다.
- 화면을 닫으면 같은 위치와 방향에서 이동을 재개한다.
- 실내 공간으로 이동하지 않고 포트폴리오, 지역 설명, NPC 대화를 화면 위 UI로 표시한다.

## 상태 발행과 성능

3D 프레임 상태와 React UI 상태를 분리한다.

- 위치, 속도, 카메라 보간은 프레임 루프 내부에서 갱신한다.
- 지도, 지역명, 상호작용 UI에 필요한 스냅샷만 제한된 빈도로 React에 발행한다.
- 지역이나 상호작용 대상이 바뀌면 즉시 발행한다.
- 매 프레임 React 렌더링을 발생시키지 않는다.

목표 성능은 다음과 같다.

- 데스크톱 3회 측정의 중앙 평균 `55 FPS` 이상, 하위 5% 프레임 `40 FPS` 이상
- 모바일 제한 환경 3회 측정의 중앙 평균 `42 FPS` 이상, 하위 5% 프레임 `24 FPS` 이상
- 이동 중 Canvas와 장면 루트 재생성 `0회`
- 지역 이동을 위한 추가 네트워크 요청 `0회`
- 플레이에 필요한 핵심 자산 404 `0건`
- 처리되지 않은 브라우저 예외 `0건`
- 준비 시간 이후 `250ms`를 넘는 단일 프레임 `0건`

### 성능 측정 계약

합격 판정의 참조 장비는 `MacBook Pro Mac16,7`, Apple M4 Pro `14-core CPU / 20-core GPU`, 메모리 `48GB`, 전원 연결, 저전력 모드 해제 상태다. 다른 장비의 결과는 비교 자료로 기록할 수 있지만 이 성능 합격 판정을 대신하지 않는다.

두 환경 모두 참조 장비에서 `@playwright/test 1.61.1`이 설치한 Chromium, production build와 하드웨어 가속 WebGL을 사용한다. 실행마다 브라우저 버전, 운영체제, CPU, 메모리, `devicePixelRatio`, WebGL renderer, 시작·종료 품질 단계를 결과에 기록한다.

#### 데스크톱

- 뷰포트 `1440x900`
- `deviceScaleFactor: 1`
- 초기 품질 `high`
- 월드 준비 후 `5초` 대기
- 달리기 고정 경로 약 `64.3초`와 하나비 카메라 회전 `10.7초`를 합쳐 `75초`씩 3회 측정

#### 모바일 제한 환경

- 뷰포트 `390x844`
- `deviceScaleFactor: 3`
- touch·mobile 모드
- Chrome DevTools Protocol CPU 제한 `4x`
- 초기 품질 `medium`, 적응형 품질 허용
- 월드 준비 후 `5초` 대기
- 같은 달리기 경로와 카메라 회전을 합쳐 `75초`씩 3회 측정

모바일 제한 환경은 재현 가능한 자동 성능 기준이며 물리 휴대전화 측정으로 표현하지 않는다. 물리 휴대전화를 사용할 수 있으면 같은 공개 URL과 경로를 추가 확인하고 기기명을 결과에 기록한다.

FPS는 `requestAnimationFrame` 간격으로 계산한다. 평균은 유효 프레임 수를 유효 측정 시간으로 나눈 값이고, 하위 5% 값은 프레임 시간 상위 5% 구간을 FPS로 변환한 값이다. 탭 비활성화, 리사이즈와 첫 자산 로딩 시간은 측정에서 제외한다.

성능이 낮아질 때 다음 순서로 품질을 조절한다.

1. 픽셀 비율
2. 그림자 해상도와 갱신 빈도
3. 불꽃 입자 수
4. 먼 거리 장식물 표시 거리
5. NPC 보조 동작

지형, 길, 충돌, 주요 랜드마크와 플레이어는 품질 조절로 제거하지 않는다.

## 로딩과 오류 처리

### 초기 로딩

- Canvas, 핵심 지형, 선택 캐릭터의 진행 상태를 표시한다.
- 월드를 조작할 수 있는 시점을 명확히 표시한다.
- 로딩 중 입력이 런타임에 누적되지 않게 한다.

### 자산 실패

- 캐릭터 GLB 실패는 기본 3D 캐릭터로 대체한다.
- 특정 장식이나 NPC 실패는 해당 요소만 제외하고 월드를 계속 실행한다.
- 지형, 길, 충돌처럼 이동에 필요한 데이터 실패는 재시도 가능한 오류 화면으로 전환한다.
- 실패한 자산 경로와 오류 종류는 개발 로그에 남기되 개인정보와 전체 요청 URL은 남기지 않는다.

### WebGL과 런타임 실패

- WebGL 지원 여부를 Canvas 생성 전에 확인한다.
- 지원하지 않으면 지원 불가 안내와 재시도 방법을 표시한다.
- 고정 이미지 월드로 자동 전환하지 않는다.
- 장면 오류 경계를 통해 빈 화면을 방지한다.
- 재시도 시 Canvas와 런타임을 안전하게 다시 생성한다.

### 실패 주입 검증

오류 처리는 실제 실패를 주입해 확인한다.

| 실패 | 주입 방법 | 합격 조건 |
| --- | --- | --- |
| 플레이어 GLB 404 | Playwright route에서 선택 캐릭터 모델 요청에 HTTP `404` 응답 반환 | `10초` 안에 기본 3D 캐릭터가 표시되고 이동 가능 |
| NPC·장식 404 | 대상 자산 요청에 HTTP `404` 응답 반환 | 해당 요소만 빠지고 월드 이동과 다른 상호작용 유지 |
| 월드 핵심 데이터 오류 | 테스트 주입 지점에서 로더 reject | 빈 화면 없이 오류 화면과 재시도 버튼 표시 |
| WebGL 미지원 | Canvas `webgl2`·`webgl` context 반환을 `null`로 대체 | Canvas를 만들지 않고 지원 불가 안내 표시 |
| 장면 렌더 오류 | `WorldScene` 테스트 경계에서 예외 발생 | 오류 경계가 예외를 처리하고 처리되지 않은 예외 `0건` |

재시도 테스트는 실패 주입을 제거한 뒤 실행한다. 버튼을 누른 뒤 `10초` 안에 `worldReady=true`가 되고, Canvas와 런타임은 각각 한 번만 새로 만들어져야 한다. 실패 전 입력과 부분 로딩 상태를 재사용하지 않는다.

## 권위 문서와 검증 전환

### 시각 검증

`public/assets/world/world-environment-concept.png`는 색감, 지역 특징과 대표 장소의 시각 기준으로만 사용한다. 픽셀 일치나 고정 배경 합성 기준으로 사용하지 않는다.

데스크톱과 모바일에서 다음 화면을 캡처한다.

- 공항 시작
- 도쿄 마을
- 규카츠 거리
- 사쿠라 운하와 다리
- 하나비 축제장
- 좁은 골목 카메라
- 장애물 회피 카메라
- 미니맵
- 전체 지도
- NPC 상호작용

지역 캡처 값은 `tests/fixtures/rpg-visual-camera-fixtures.ts`에 두며 자동 캡처와 검증기가 같은 상수를 가져온다. focus는 각 도착점의 `[x, getSurfaceHeight(x,z) + 1.15, z]`다. yaw offset은 도착점 heading에서 회전한 값이다.

| 지역 | yaw offset | pitch | 데스크톱 거리 | 모바일 거리 |
| --- | ---: | ---: | ---: | ---: |
| 공항 | `-25°` | `28°` | `7.8` | `6.864` |
| 도쿄 | `30°` | `34°` | `6.6` | `5.808` |
| 규카츠 | `-20°` | `38°` | `5.6` | `4.928` |
| 사쿠라 | `25°` | `32°` | `6.8` | `5.984` |
| 하나비 | `-30°` | `28°` | `8.0` | `7.04` |

독립 검토자는 각 지역에서 다음 필수 요소를 확인한다.

| 지역 | 화면에 보여야 하는 요소 |
| --- | --- |
| 공항 | 터미널, 공항 버스, 넓은 진입 광장 |
| 도쿄 | 높은 건물, 교차로 또는 횡단보도, 간판 |
| 규카츠 | 낮은 마치야, 화로 또는 음식 소품, 좁은 골목 |
| 사쿠라 | 운하, 통과 가능한 다리, 벚나무 |
| 하나비 | 도리이, 등불·노점, 불꽃놀이 |

필수 요소가 하나라도 없거나 다른 지역의 대표 요소가 주인공처럼 보이면 해당 캡처는 실패다. 기준 이미지와의 평가는 색상 계열, 형태 비율, 랜드마크 식별성과 장면 밀도를 항목별로 승인하며 픽셀 유사도 점수 하나로 대체하지 않는다.

검토 항목은 다음과 같다.

- 선택한 캐릭터가 정확한지
- 발이 지면에 맞는지
- 지역별 배경이 분명히 다른지
- 이동 방향과 카메라 방향이 자연스러운지
- 카메라가 건물 안에 들어가지 않는지
- 캐릭터가 장시간 가려지지 않는지
- 지도 위치와 실제 위치가 일치하는지
- 모바일 UI가 이동과 카메라 조작을 막지 않는지

## 완료 조건

- 활성 월드가 하나의 지속되는 3D Canvas다.
- 고정 배경 이미지와 기준 이미지 카메라가 활성 렌더링 경로에 없다.
- 선택한 실제 3D 캐릭터로 공항부터 하나비까지 이동할 수 있다.
- 지역 사이에 순간이동, 로딩 화면, 장면 재생성이 없다.
- 모든 일반 이동은 충돌과 보행 가능 영역을 통과한다.
- 보행 가능 고정 경로 `122.09 world units`의 모든 표본이 `isWalkable=true`이고 걷기 `75.8초`, 달리기 `64.3초`의 `±5%`를 만족한다.
- 평지와 다리에서 캐릭터 발과 지면 오차가 `0.02 world units` 이하다.
- 이동에 따라 지형, 건물, 식생, 조명, 효과와 카메라 구도가 변한다.
- 데스크톱과 모바일에서 자유 카메라 회전이 동작한다.
- 카메라는 마지막 회전 입력 `0.8초` 뒤 복귀를 시작하고 `1.2초` 안에 이동 뒤쪽 `5°` 이내에 도달한다.
- 카메라는 장애물을 피하면서 최소 boom 거리 `2.6`과 화면 안전 영역을 유지한다.
- 지도 도착점 오차 `0.5 CSS px`, 평면 왕복 오차 `0.1 world units`, 방향 오차 `2°`, 반영 지연 `100ms` 이하를 만족한다.
- 전체 지도는 캐릭터 위치를 변경하지 않는다.
- 활성 입력과 런타임에 `queueTravel`, `consumeTravel`, `fastTravel`, `teleport`, 외부 `setPosition`이 없다.
- NPC와 주요 입구 상호작용 후 같은 위치에서 이동을 재개한다.
- 정의된 3회 측정에서 데스크톱 중앙 평균 55FPS·하위 5% 40FPS, 모바일 제한 환경 중앙 평균 42FPS·하위 5% 24FPS 이상을 만족한다.
- 주입한 캐릭터·NPC·핵심 데이터·WebGL·장면 실패가 정해진 fallback과 재시도 조건을 만족한다.
- 단위, 구성 요소, 브라우저, 시각 검증이 통과한다.
- Computer Use로 핵심 이동과 조작을 확인한다.
- 공개 URL에서 콘솔 오류, 핵심 자산 404, 처리되지 않은 예외가 없다.
- 검증된 로컬·PR·포크 SHA가 일치하고 해당 SHA의 Sites 버전이 공개 URL에 배포된다.
- 활성 문서와 기본 테스트가 연속 3D 월드를 설명하고 G005·G007 자료는 변경되지 않은 역사 증거로 남는다.

## 주요 위험과 대응

### 절차형 배경과 대표 장소의 스타일 불일치

- 지역별 색상, 재질 거칠기, 윤곽 비율, 창문 크기, 소품 밀도 규칙을 공유한다.
- 대표 장소를 추가할 때 같은 지역의 반복 건물과 나란히 시각 검토한다.

### 3D 코드 활성화로 인한 구형 좌표 혼입

- 구면 `WorldSession`을 활성 경로에서 사용하지 않는다.
- 모든 장면 배치, 충돌, 지도 투영에 `RpgWorldModel` 좌표를 사용한다.
- 좌표 출처가 둘 이상 생기는 변경을 테스트와 코드 검토에서 차단한다.

### 모바일 성능 저하

- 반복 물체는 인스턴싱하고 장식물 표시 거리를 제한한다.
- 품질 저하 순서를 고정해 핵심 지형과 플레이어를 보호한다.
- 모바일 실제 브라우저에서 지역별 FPS를 측정한다.

### 카메라와 조작 충돌

- UI 포인터 영역과 월드 카메라 영역을 분리한다.
- 이동 방향은 카메라 수평 각도만 사용한다.
- 장애물 회피, 자동 복귀, 모바일 드래그를 독립 테스트한다.

### 빠른 이동 기능의 잔존

- 지도 선택 콜백에서 위치 변경 권한을 제거한다.
- 런타임 외부에서 좌표를 바꿀 수 있는 경로를 재시작 하나로 제한한다.
- 지도 상호작용 뒤 위치가 바뀌지 않는 브라우저 테스트를 추가한다.
