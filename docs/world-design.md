# 월드 디자인

## 활성 구성

```text
ExperienceShell
→ WorldView
→ SeamlessWorldCanvas
→ WorldRuntime + RpgTownScene + RpgPlayerActor + ChaseOrbitCamera3d
```

`RpgTownScene`은 지형, 도로, 다리, 운하, 건축물, 랜드마크, NPC와 효과를 하나의 Three.js 장면에 배치한다. `WorldRuntime`은 같은 좌표계에서 이동, 충돌, 점프, 구역과 상호작용을 계산한다.

## 좌표와 경로

월드 경계는 `x=-36..36`, `z=-36..36`이다. 장소는 `airport`, `tokyo`, `gyukatsu`, `sakura`, `hanabi`다.

공항에서 하나비까지의 기준 경로는 `tests/fixtures/rpg-canonical-route.ts`에 있다. 총 길이 `122.08884600503183`을 걷기 `3`, 달리기 `7` 속도로 이동한다.

## 이동 방향

키 입력은 화면 기준으로 읽고 카메라 기준으로 월드 방향이 된다. 화면 위는 카메라에서 멀어지는 쪽, 화면 오른쪽은 카메라의 오른손 쪽이다. 위에서 내려다본 지면 평면은 좌우 손잡이가 뒤집히므로, 화면 기준을 월드로 옮기는 변환은 회전이 아니라 반사여야 한다. 회전을 쓰면 앞뒤는 맞고 좌우만 모든 각도에서 반대가 된다.

기준축은 `ChaseOrbitCamera.getChaseOrbitCameraBasis`가 유일한 출처다. 카메라 배치(`getChaseOrbitCameraOffset`), 런타임 이동(`resolveCameraRelativeDirection`), 테스트 조향(`tests/fixtures/rpg-route-steering.ts`)이 모두 이 함수를 읽는다. 어느 하나가 같은 계산을 따로 적어 두면 조용히 어긋난다.

카메라 자동 복귀는 앞으로 걷는 입력에서만 걸린다. 옆으로 걷는 동안에도 진행 방향을 쫓으면, 이동 방향이 카메라 기준이므로 카메라와 진행 방향이 서로를 밀며 제자리에서 돈다.

## 충돌과 통행

- 월드 경계, 구조물과 물 영역을 통과할 수 없다.
- 운하 범위는 `x=15.5..17.7`이다.
- 운하는 `sakura-bridge-route`의 `z=-18..-16` 범위에서만 건널 수 있다.
- 동적 공항버스와 NPC는 런타임 카메라·이동 장애물로 갱신된다.

## 카메라

`ChaseOrbitCamera3d`는 플레이어를 중심으로 회전하는 원근 카메라다.

- 장소별 거리와 피치 프로필을 부드럽게 적용한다.
- 마우스·터치 드래그로 요와 피치를 바꾼다.
- 마지막 수동 입력 후 `0.8초`가 지나고 이동 중이면 진행 방향 뒤로 복귀한다.
- 정적·동적 장애물과 충돌해 카메라 붐을 줄이되 `2.6` 아래로 내리지 않는다.
- 화면 안전 영역 보정과 제한된 랜드마크 투명화를 사용한다.
- 요, 피치, 붐, 안전 위반 시간과 진단을 렌더러 데이터 속성으로 공개한다.

## 지도

미니맵과 전체 지도는 월드 모델을 `1817x866` 참고 좌표로 투영한다. 이 좌표는 지도 등록용이며 활성 3D 배경 이미지가 아니다.

런타임은 보통 이동을 `75ms` 간격으로 UI에 발행하고 구역·상호작용 변화는 즉시 발행한다. 지도 플레이어 마커는 런타임과 같은 `data-navigation-revision`을 사용한다.

전체 지도 장소 버튼은 선택 설명만 바꾸며 플레이어 위치, 방향과 탐색 리비전을 변경하지 않는다.

## 성능

프로덕션 서버에서 5초 준비 시간을 제외하고 정확히 75초를 측정한다. 각 데스크톱·제약 모바일 프로젝트를 세 번 실행한다.

- 데스크톱 중앙값 평균/하위 5% FPS: `55/40` 이상
- CPU 4배 제한 모바일 중앙값 평균/하위 5% FPS: `42/24` 이상
- `250ms` 초과 프레임, 구역 전환 요청, 요청 실패, 페이지·콘솔 오류: `0`
- Canvas, 런타임, 장면 생성 횟수: 각각 `1`
