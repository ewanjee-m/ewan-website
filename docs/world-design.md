# 월드 디자인

## 원칙

월드는 승인된 `/assets/world/world-environment-concept.png`를 화면의 시각 기준으로 사용한다. 원본 크기 `1817x866`을 배경, 카메라 표시 창, 플레이어, 접촉 그림자, 전경 가림, 미니맵과 전체 지도의 공통 이미지 좌표로 등록한다.

논리 이동과 충돌은 별도의 월드 좌표에서 계산한다. 화면에 보이는 원화와 논리 월드는 교정점, 도착점과 경로를 통해 연결된다.

## 활성 구성

활성 경로는 `ExperienceShell -> WorldView -> FlatWorldCanvas`다.

`FlatWorldCanvas`는 다음 순서로 화면을 합성한다.

1. `RpgWorldBackdrop`이 승인 원화의 현재 표시 창을 그린다.
2. 플레이어 접촉 그림자를 배치한다.
3. 투명 Canvas 2D에 플레이어 WebP 스프라이트를 그린다.
4. `RpgReferenceSceneComposition`이 현재 구역의 잘라 낸 전경을 플레이어 위에 겹친다.
5. `WorldView`가 포트폴리오, 길 안내, 미니맵, 전체 지도와 조작 UI를 배치한다.

배경, 그림자, 플레이어와 전경은 같은 탐색 리비전과 화면 변환을 사용한다. 일부 계층만 갱신되면 화면을 준비 완료로 표시하지 않는다.

## 논리 월드

월드 경계는 다음과 같다.

```text
x = -36..36
z = -36..36
```

다섯 장소는 `airport`, `tokyo`, `gyukatsu`, `sakura`, `hanabi`다. 각 장소에는 다음 정보가 있다.

- 논리 구역 다각형
- 주요 장소와 보호 영역
- 원화의 기준 픽셀
- 전체 지도 이동 도착점과 바라보는 방향
- 카메라가 함께 보여 줘야 하는 원화 영역

공항에서 시작해 도쿄와 규카츠로 이동하고, 규카츠에서 벚꽃 수로, 벚꽃 수로에서 하나비로 이어진다. 각 경계의 연결 구간은 어느 장소가 카메라와 전경을 소유하는지 명시하며, 전환 중에는 양쪽 주요 장소 보호 범위를 함께 고려한다.

## 경로와 충돌

이동 가능 여부는 `RpgWorldGeometry`가 판정한다.

- 월드 경계 밖으로 나갈 수 없다.
- 등록된 경로와 장소의 통행 영역을 사용한다.
- 구조물 차단 영역을 통과할 수 없다.
- 벚꽃 수로의 운하는 물 영역이므로 통과할 수 없다.
- 운하는 `sakura-bridge-route`로 등록된 다리에서만 건널 수 있다.

미니맵과 전체 지도는 같은 지형, 장소 다각형, 연결 경로와 다리를 투영한다. 따라서 화면의 길, 논리 이동 경로와 지도 경로가 서로 다른 데이터로 갈라지지 않는다.

## 이미지 등록

월드 모델은 `1817x866` 원화에 다음 정보를 등록한다.

- 다섯 장소의 주요 대상
- 다섯 전체 지도 이동 도착점
- 해안선과 운하 양쪽
- 다리와 연결 경로 제어점
- 플레이어가 건물이나 난간 뒤로 지나가는 깊이 구간

원화 좌표는 왼쪽 위가 원점이다. 논리 월드의 `x`축은 원화 오른쪽, `z`축은 원화 위쪽 방향으로 등록된다. 비선형 원근 차이는 교정 메시로 보정한다.

## 카메라 표시 창

카메라는 원화를 입체 시점으로 회전하지 않는다. 플레이어의 등록된 발 픽셀과 장소 보호 범위를 기준으로 원화의 일부를 화면에 확대·이동한다.

| 프로필 | 뷰포트 | 안전 프레임 |
| --- | --- | --- |
| `desktop` | `1440x900` | `(0,0,1440,900)` |
| `mobile` | `390x844` | `(0,64,390,780)` |

데스크톱은 원화 높이 `866`을 화면 높이 `900`에 맞춘다. 모바일은 `1.3` 배율의 세로 표시 창을 사용하고 상단 `64px`을 UI 영역으로 비운다.

보통 이동에서는 한 프레임의 화면 이동을 제한한다. 전체 지도 이동, 위치 초기화, 화면 크기 변경과 오류 복구는 이전 보간 상태를 끌고 가지 않고 동일한 탐색 리비전으로 배경, 플레이어, 그림자와 전경을 다시 등록한다.

## 플레이어 합성

플레이어의 논리 위치를 원화의 발 픽셀로 투영한다. 스프라이트는 그 발 픽셀을 기준으로 위쪽에 그린다.

- 데스크톱 표시 높이는 장소에 따라 `128~144px`이다.
- 모바일 표시 높이는 `122px`이다.
- 프레임별 발 오프셋으로 투명 여백을 보정한다.
- 정면·후면·측면과 두 달리기 프레임을 사용한다.
- 왼쪽 측면은 오른쪽 자산을 가로 반전한다.
- 접촉 그림자는 스프라이트보다 아래 계층에 놓고 점프 중에도 지면 위치를 유지한다.

## 전경 가림

각 장소에는 승인 원화에서 잘라 낸 전경 마스크가 있다.

- 공항: 정류장 보호대와 화단
- 도쿄: 거리 가장자리
- 규카츠: 등불과 건물
- 벚꽃 수로: 나무와 수로 난간
- 하나비: 난간과 기둥

플레이어가 등록된 깊이 경계를 넘으면 해당 전경을 플레이어 위에 표시한다. 전경은 별도 그림이 아니라 승인 원화와 같은 자산을 같은 변환으로 잘라 사용한다.

## 지도와 전체 지도 이동

미니맵과 전체 지도는 다음 데이터를 공유한다.

- 승인 원화 지형과 해안선
- 다섯 장소
- 경로와 다리
- 다섯 도착점
- 플레이어 위치와 진행 방향

전체 지도에서 장소를 선택하면 `WorldView`가 목적지를 `InputController`에 넣는다. `FlatWorldCanvas`는 다음 프레임에서 `FlatWorldSession.fastTravel`을 실행하고 위치, 방향, 현재 구역, 카메라 표시 창과 지도 스냅샷을 한 번에 갱신한다. 중간 위치를 보여 주는 이동 애니메이션은 없다.

## GPU 검증 의미

활성 렌더러는 `CanvasRenderingContext2D`를 사용하며 WebGL 또는 WebGL2 컨텍스트를 만들지 않는다. GPU 메모리 측정은 대상이 없으므로 상태가 `NOT_APPLICABLE`이다.

```text
active renderer uses CanvasRenderingContext2D and creates no WebGL/WebGL2 context
```

`0`바이트는 GPU 메모리를 측정한 결과처럼 오해될 수 있으므로 사용하지 않는다.
